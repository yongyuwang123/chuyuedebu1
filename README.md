## 一、项目定位

- 取代实体铜钱，通过前端交互 + 时间戳随机数模拟"摇卦"。
- 自动完成：**起卦 → 装卦 → 排盘 → 解卦（爻辞 + 五行提示）** 全链路。
- 体验目标：玄黑底、朱砂红高亮、宣纸白文字、青铜金铜钱，配合"哗啦"铜钱声与逐爻旁白，营造仪式感。
- 价值：既是练习六爻的利器，也是简历上极具辨识度的跨界个人项目。

## 二、核心功能模块（MVP）

### 1. 起卦模块（仪式感）
- 用户先静心，输入所问之事（如"去不去平安财险"）。
- 界面中央三枚虚拟铜钱，点击"摇卦"按钮（长按/连点 + 动画）。
- 随机种子：`Date.now()` + `performance.now()` 的微秒级尾数，或 `event.timeStamp` 尾数（代表"按下那一刻的意念机锋"），**不使用纯 `Math.random()`**。
- 连续摇 **6 次**，从下往上生成 **初爻 → 上爻**。

### 2. 排盘模块（技术硬核）
- 识别老阴 / 老阳 / 少阴 / 少阳，定出**本卦**与**变卦**。
- 自动计算：定**世应**（八宫卦序规则）、装**干支**（纳甲法）、配**六亲**（基于卦宫五行）、安**六神**（基于日干）。
- 输出每爻：阴阳、动静、地支、五行、六亲、六神、世/应标识。

### 3. 解卦模块（诗意输出）
- 显示本卦、变卦卦象（卦符）。
- 提取动爻，展示该爻《易经》原文（爻辞）+ 白话解析。
- 基础五行生克提示：世应关系、动爻对世爻的生克。

## 三、技术栈建议（定稿：纯前端内嵌算法）

> **架构决策：纯前端，不写后端。** 六爻排盘是纯计算逻辑（无数据库、无高并发、无外部 IO），FastAPI 属"杀鸡用牛刀"。纯前端可免费部署（Vercel / Netlify / GitHub Pages）、用户数据不出本地（算卦属隐私）、可做 PWA 离线使用；核心算法抽离为独立纯函数模块（`src/core/liuyao.ts`），实现算法与 UI 解耦，面试时可称"核心算法与 UI 解耦的纯函数库"。

### 3.1 推荐技术栈（二选一，二者皆可用）

**默认采用（作者前端栈以 Vue 3 为主，降低交付风险）：**
`Vite + Vue 3 + TypeScript + Pinia + Tailwind CSS + @vueuse/motion（或 motion-v）+ Web Audio API（或 howler.js）+ Vitest + Vercel`

**平替（React 路线，动画生态更成熟）：**
`Vite + React 18 + TypeScript + Zustand + Tailwind CSS + Framer Motion + Web Audio API（或 howler.js）+ Vitest + Vercel`

> 选型原则：框架跟着**最熟的手感**走，而非跟着求职岗位走。本仓库默认 Vue 3 组合；React 组合在动画（Framer Motion）上更成熟，亦可平替。

### 3.2 各层职责与简历话术

| 层 | 选型 | 作用 | 简历话术 |
|----|------|------|----------|
| 构建 | Vite | 极速启动、原生 TS | "基于 Vite + Vue3/React + TS 构建的高性能前端应用" |
| 状态 | Pinia / Zustand | 管理起卦状态机（当前爻、硬币数组、排盘结果） | "用 Pinia/Zustand 管理复杂起卦状态机，避免状态污染" |
| 样式 | Tailwind CSS | 宣纸底/水墨字体/朱砂红 | 古风 UI 体系 |
| 动画 | @vueuse/motion / Framer Motion | 铜钱翻转、爻线生成 | "结合 Motion 打造沉浸式交互，铜钱摇落微动画" |
| 音效 | Web Audio API / howler.js | 铜钱碰撞声、出卦提示音 | "Web Audio API 实现音效反馈，仪式感拉满"（推荐直接合成"哗啦"声，零素材依赖） |
| 测试 | Vitest ⭐ | 排盘算法单测（世爻/纳甲/六亲断言） | "为纳甲/六亲算法写 50+ Vitest 单测，确保 100% 符合《卜筮正宗》" |
| 部署 | Vercel + GitHub Actions | 推送即测即部署 | "GitHub Actions CI/CD 自动跑测试并部署 Vercel" |

> ⚠️ **音效自动播放防坑**：iOS/Chrome 在用户首次交互前 `AudioContext` 处于 `suspended`，第一下摇卦可能无声。必须在用户点击"摇卦"按钮的瞬间初始化并 `resume()` AudioContext——这也契合六爻"心动起卦"的交互（点击即唤醒声音）。

### 3.3 单元测试是杀手锏
玄学排盘最怕算错。须为 `src/core/liuyao.ts` 编写 Vitest 用例，至少覆盖：
- 喂"乾为天" → 断言世爻在第 6 爻（上爻）、八纯卦皆六冲；
- 喂"泽火革"（上兑下离）→ 断言纳甲地支为 卯、丑、亥（下卦离）、亥、酉、未（上卦兑）；
- 六亲按本卦卦宫（乾宫金：水=子孙、木=妻财、土=父母、火=官鬼、金=兄弟）；
- 空亡随日柱变化、六神随日干变化、变卦六亲仍按本卦卦宫。

数据源：64 卦 JSON 字典见 §九，取现成开源数据，勿手敲。

## 四、六爻核心规则（技术规格）

> 本章是排盘算法的"真理之源"。实现后须对照《卜筮正宗》《增删卜易》逐条校验，AI 常在纳甲口诀上出错。

### 4.1 起卦基础（三枚铜钱）

约定（主流"三钱法"，以"背"为阳面）：

| 铜钱结果 | 阴阳 | 称 | 数 | 动静 | 变否 |
|----------|------|----|----|------|------|
| 三背 | 阳 | 重（○） | 9 | 老阳 | **变**（阳极生阴） |
| 两背一字 | 阴 | 拆 | 8 | 少阴 | 不变 |
| 一背两字 | 阳 | 单 | 7 | 少阳 | 不变 |
| 三字 | 阴 | 交（×） | 6 | 老阴 | **变**（阴极生阳） |

- 6 次结果从下往上叠成六爻：第 1 次 = 初爻，第 6 次 = 上爻。
- 老阳（9）、老阴（6）为**动爻**；少阳（7）、少阴（8）为静爻。

> ⚠️ **UI 必须明示约定**：本工具统一采用"以背为阳"。存在"以字为阳"的流派，结果会完全相反；起卦界面需明确标注当前约定（如"背=阳"），避免用户误读。

> **硬币映射防呆**：`tossCoins()` 应先返回 3 枚铜钱的正反面数组（如 `1`=背、`0`=字，即 `[1,1,0]`），再按"背的数量"映射为 6/7/8/9（0背=老阴6、1背=少阳7、2背=少阴8、3背=老阳9）。保留原始数组，便于 UI 展示"具体哪几枚是背/字"。

### 4.2 装卦总览（执行顺序）

1. 由六爻阴阳组合确定上下卦：下三爻（初/二/三）组成本卦下卦，上三爻（四/五/上）组成本卦上卦；将上下经卦组合后查京房八宫表 → 得**本卦**与所属**卦宫**（便于后续直接定位世应）。
2. 动爻阴阳反转 → 得**变卦**。
3. 据卦宫定**世爻**位置 → 推算**应爻**（应 = 世 + 3，循环 1–6）。
4. **纳甲**：按卦宫内/外卦装配十二地支。
5. **装六亲**：以**卦宫五行**为"我"，按纳支五行生克定六亲。
6. **安六神**：以**日干**起六神，从初爻上排。
7. 输出五行生克提示。

### 4.3 八宫卦序与世应

八宫各纯卦五行：乾兑=金，离=火，震巽=木，坎=水，艮坤=土。

世爻位置规律：

| 卦别 | 世爻位置 |
|------|----------|
| 纯卦（本宫） | 上爻（6） |
| 一世卦 | 初爻（1） |
| 二世卦 | 二爻（2） |
| 三世卦 | 三爻（3） |
| 四世卦 | 四爻（4） |
| 五世卦 | 五爻（5） |
| 游魂卦 | 四爻（4） |
| 归魂卦 | 三爻（3） |

**应爻 = 世爻位置 + 3（取 1–6 循环）**，如世在初爻则应在四爻，世在上爻则应在三爻。

### 4.4 纳甲法（装地支）

按"下卦（内）= 初/二/三爻，上卦（外）= 四/五/上爻"装配，从初爻到上爻：

| 经卦 | 初爻 | 二爻 | 三爻 | 四爻 | 五爻 | 上爻 |
|------|------|------|------|------|------|------|
| 乾 | 子 | 寅 | 辰 | 午 | 申 | 戌 |
| 坤 | 未 | 巳 | 卯 | 丑 | 亥 | 酉 |
| 震（同乾） | 子 | 寅 | 辰 | 午 | 申 | 戌 |
| 坎 | 寅 | 辰 | 午 | 申 | 戌 | 子 |
| 艮 | 辰 | 午 | 申 | 戌 | 子 | 寅 |
| 巽 | 丑 | 亥 | 酉 | 未 | 巳 | 卯 |
| 离 | 卯 | 丑 | 亥 | 酉 | 未 | 巳 |
| 兑 | 巳 | 卯 | 丑 | 亥 | 酉 | 未 |

**十二地支五行**：子(水) 丑(土) 寅(木) 卯(木) 辰(土) 巳(火) 午(火) 未(土) 申(金) 酉(金) 戌(土) 亥(水)。

> 口诀记忆：乾震"子寅辰/午申戌"；坤"未巳卯/丑亥酉"；其余按"阳顺阴逆、对宫交错"推导，实现后以八纯卦为基准单元校验。

### 4.5 装六亲（基于卦宫五行）⚠️ 修正 PRD

> **重要纠正**：原 PRD 写"配六亲基于日干"是**错误的**。六亲以**卦宫五行**为"我"（日主），与日干无关；**日干用于安六神**（见 4.6）。

以卦宫五行为"我"，按纳支五行生克：

| 关系 | 六亲 |
|------|------|
| 同我（比和） | 兄弟 |
| 我生 | 子孙 |
| 我克 | 妻财 |
| 克我 | 官鬼 |
| 生我 | 父母 |

示例：乾宫（金）某爻纳支为"子(水)"，水泄金（我生）→ 子孙；纳支"寅(木)"，金克木（我克）→ 妻财。

> **关键（易错点）**：无论本卦还是变卦，六亲一律以**本卦卦宫五行**为"我"判定。例：乾宫卦变出他宫卦象，变爻六亲仍按乾金推算，不可改用变卦所在宫。此点已由开源实现（如 `bopo/najia`）证实——变卦六亲误用变卦宫是常见 bug。

### 4.6 安六神（基于日干）【补充 PRD 遗漏】

| 日干 | 初爻起神 | 顺序（初→上） |
|------|----------|----------------|
| 甲、乙 | 青龙 | 青龙→朱雀→勾陈→螣蛇→白虎→玄武 |
| 丙、丁 | 朱雀 | 朱雀→勾陈→螣蛇→白虎→玄武→青龙 |
| 戊 | 勾陈 | 勾陈→螣蛇→白虎→玄武→青龙→朱雀 |
| 己 | 螣蛇 | 螣蛇→白虎→玄武→青龙→朱雀→勾陈 |
| 庚、辛 | 白虎 | 白虎→玄武→青龙→朱雀→勾陈→螣蛇 |
| 壬、癸 | 玄武 | 玄武→青龙→朱雀→勾陈→螣蛇→白虎 |

### 4.7 五行生克与旺衰

- 相生：木→火→土→金→水→木
- 相克：木克土、土克水、水克火、火克金、金克木
- 旺衰参考（月建）：寅卯月木旺、巳午月火旺、申酉月金旺、亥子月水旺、辰戌丑未月土旺。
- ⚠️ **月建按节气划分，非农历月份**：立春建寅、惊蛰建卯、清明建辰、立夏建巳、芒种建午、小暑建未、立秋建申、白露建酉、寒露建戌、立冬建亥、大雪建子、小寒建丑。代码须以节气（太阳黄经）定月建，否则旺衰判断失真。

**4.7.1 空亡（旬空）**：依起卦日柱干支推旬空。六十甲子分六旬，每旬缺两干支为空亡（甲子旬戌亥空、甲戌旬申酉空、甲申旬午未空、甲午旬辰巳空、甲辰旬寅卯空、甲寅旬子丑空）。旬空之爻"空"而暂不能实生克他爻，须结合出空（冲空、填实）判断；排盘须标注各爻是否空亡。

**4.7.2 六冲与六合**：排盘须标注本/变卦是否六冲或六合。八纯卦（乾兑离震巽坎艮坤）皆六冲；天雷无妄、雷天大壮亦六冲。六合卦指六爻地支两两相合（子丑、寅亥、卯戌、辰酉、巳申、午未相合），如天地否、地天泰、雷地豫、水泽节等。六冲主散、六合主聚，为断卦参考维度。

解卦提示要点（**仅展示关系，不下断语**）：系统只输出五行生克关系（如"动爻X 生/克 世爻""应爻 生/克 世爻"），**不自动判定吉凶**。最终判断由用户结合用神、月建日辰旺衰自行得出。应爻代表所问之事/对方，世爻代表问卦者自身。

### 4.8 变卦与动爻

- 本卦动爻（老阳变阴 / 老阴变阳）逐爻反转 → 变卦。
- 若六爻皆静（无 6/9），则无变卦，仅看本卦卦辞与六爻静象。
- 多爻动时的"主变爻"取法：本工具参考**朱熹变占法**（多爻动可侧重最上动爻），但仅为一种约定；火珠林/纳甲筮法主流更看重动爻间生克与用神。代码中仅作提示，实际断卦须结合用神灵活判断，不可机械套用。

## 六、数据字典规范

需一份 JSON，结构建议：

```jsonc
{
  "guas": [
    {
      "id": 1,                 // 先天/京房序号
      "name": "乾",            // 卦名
      "symbol": "☰",           // 卦符
      "gong": "乾",            // 所属卦宫
      "gongWuxing": "金",      // 卦宫五行
      "guaCi": "元亨利贞。",    // 卦辞
      "lines": [               // 从初爻到上爻；数组下标 0=初爻 … 5=上爻（注意 1-based 爻位与 0-based 下标的映射）
        { "yao": 1, "yaoCi": "初九：潜龙勿用。", "baihua": "..." }
      ]
    }
  ]
}
```

- 共 64 卦，每卦 6 爻辞，合计 384 爻辞。
- 字段须含：卦名、卦符、卦宫、卦宫五行、卦辞、六爻爻辞（带爻题如"初九"）、白话解析。
- ⚠️ **爻位索引防呆**：爻位用 1–6（初爻=1，上爻=6），但数组下标是 0–5（0=初爻，5=上爻）。世/应/动爻定位时务必做 `下标 = 爻位 - 1` 映射，避免"世爻在第4位却写成下标4（实为五爻）"的经典 off-by-one bug。

## 七、给 WorkBuddy 的分阶段 Prompt 模板

可复制分阶段发送（详见本仓库后续实现记录）：

- **阶段一 数据建模**：TS 定义 `Yao`（爻位/阴阳/动静/地支/五行/六亲/世应）与 `Gua` 接口，输出 64 卦 JSON 结构。⚠️ 明确 `Yao.yao`（爻位）用 1–6（初=1，上=6），数组下标 0–5（0=初），所有下标访问必须 `yao-1` 映射，杜绝 off-by-one。
- **阶段二 核心算法**：`tossCoins()` 结合 `Date.now()`+`performance.now()` 微秒尾数为种子，先返回 3 枚铜钱正反面数组（`1`=背、`0`=字，如 `[1,1,0]`），再按背的数量映射为 6/7/8/9（0背=老阴6、1背=少阳7、2背=少阴8、3背=老阳9）。保留原始数组供 UI 展示。⚠️ 勿直接使用 `Math.random()`。
- **阶段三 排盘逻辑**：`getLiuYaoInfo(benGua, riGanZhi)` —— 入参为起卦时**日干支**（非仅日干）：日干用于安六神，日支用于推旬空（空亡）；推算本卦/变卦、世应、地支五行、六亲（按本卦卦宫）、六神、空亡、六冲六合。
  ⚠️ **日干支获取方式（含真太阳时）**：不可直接用 `new Date()` 取公历推算。已由前端调用 `lunar-javascript`（已安装为依赖）将起卦时刻换算为日干支与**节气月建**（见 §4.7），并用 Vitest 锁死（见 §十）。**真太阳时依赖经度**（标准北京时间=东经120°），每偏离1度时间±4分钟；若用户未授权地理位置，默认兜底为东八区（北京时间），或在设置中手动输入起卦地经度。`lunar-javascript` 无 `SolarTime`，真太阳时由 `solar.ts` 自写经度偏移算法实现，仍走 lunar-javascript 取干支/节气。
  🔒 **信任边界（死命令）**：纳甲/世应/六亲口诀极易被 AI 幻觉篡改。阶段三实现须优先对照 `iching-shifa` / `bopo/najia` 源码；生成后必须用 Vitest 对比这些开源库的断言结果（见 §3.3、§八），不得盲信 AI 写出的玄学逻辑。
- **阶段四 UI 与文案**：React/Vue + 宣纸背景 + 古风字体，注入起卦文案，朱砂红高亮动爻与爻辞。

## 八、开发避坑指南

1. **别陷"纯算法"陷阱**：随机种子须取自用户交互时刻（`event.timeStamp` / `performance.now()` 尾数），保留"心动机锋"，而非代码运行速度。
2. **纳甲最易错**：先写粗糙代码，再对照《卜筮正宗》逐宫校验；AI 常在纳甲口诀出错。
3. **六亲 vs 六神**：六亲看卦宫五行，六神看日干，二者勿混（已纠正于 4.5/4.6）。
4. **数据别手敲**：64 卦爻辞直接取开源 JSON/API，避免错别字。
5. **修心为重**：工具只是载体，解卦仍需读《增删卜易》《卜筮正宗》积累。
6. **AI 玄学逻辑不可盲信（信任边界）**：纳甲（乾震"子寅辰/午申戌"等）口诀极易被 AI 幻觉篡改。阶段三排盘须优先查阅 `iching-shifa` / `bopo/najia` 源码实现；生成代码后必须用 Vitest 对比这些开源库的断言结果（见 §3.3），用测试锁死正确性，而非盲信 AI 输出。
